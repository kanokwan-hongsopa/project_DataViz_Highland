## PART 1 — แก้บั๊กคลิกจังหวัดบนกราฟผิด

จาก Screenshot ที่แนบ:

กราฟหัวข้อ "จังหวัดไหนมีอุณหภูมิเฉลี่ยสูงที่สุด?"

เมื่อคลิกแท่งจังหวัดกาญจนบุรี Dashboard กลับเลือกจังหวัดอื่น

นี่เป็นบั๊กที่ต้องแก้ก่อนดำเนินงานส่วนอื่น

ให้ตรวจไฟล์:

- `js/pages/overview.js`
- `js/charts.js`
- `js/state.js`
- `js/filters.js`

โดยเฉพาะฟังก์ชัน `renderOverviewProvinceRanking()` และระบบ Chart.js Click Event

ตรวจสอบสาเหตุที่เป็นไปได้:
- การใช้ `interaction.mode = 'index'` และ `intersect = false`
- การจับตำแหน่งเมาส์ของกราฟ
- การจับคู่ `element.index` กับจังหวัดหลัง Sorting
- Dataset ปี 2022 และปี 2023 มีลำดับไม่ตรงกัน
- การอัปเดต Chart Instance แล้ว Event Handler ยังอ้างข้อมูลเก่า
- การคลิกระหว่าง Chart Animation
- Canvas Resize หรือ CSS Scaling ทำให้ Hit Area คลาดเคลื่อน
- State เปลี่ยนแล้วจังหวัดที่เลือกถูกเขียนทับ

### พฤติกรรมที่ต้องการ

เมื่อคลิกแท่งกราฟของจังหวัดใด ต้องเลือกจังหวัดนั้นเท่านั้น

ตัวอย่าง:
- คลิกกาญจนบุรี → จังหวัดกาญจนบุรี
- คลิกกำแพงเพชร → จังหวัดกำแพงเพชร
- คลิกน่าน → จังหวัดน่าน
- คลิกเชียงใหม่ → จังหวัดเชียงใหม่

ห้ามเลือกจังหวัดใกล้เคียงเพราะคลิกพื้นที่ว่างของกราฟ

### วิธีแก้ทางเทคนิค

ให้ตรวจสอบการทำ Hit Testing ของ Chart.js

สำหรับการคลิกแท่งกราฟ ให้พิจารณาใช้การตรวจจับ Element ที่ผู้ใช้คลิกจริงด้วย:

`chart.getElementsAtEventForMode(event, 'nearest', { intersect: true }, true)`

หรือใช้วิธีที่เหมาะสมกว่าในเวอร์ชัน Chart.js ที่ติดตั้งอยู่

ต้องใช้จังหวัดจาก Data Mapping ที่ตรงกับแท่ง ณ เวลาคลิกจริง ไม่ใช้ Index จาก Array เก่าที่อาจเปลี่ยนหลัง Sorting

ห้าม Hard-code ลำดับจังหวัด

ถ้าคลิกนอกแท่งกราฟ ต้องไม่เปลี่ยน Province Filter โดยไม่ตั้งใจ

เพิ่ม Hover Cursor และ Tooltip เพื่อให้รู้ว่าแท่งไหนคลิกได้

ถ้าต้องการให้คลิกชื่อจังหวัดได้ด้วย ให้ทำ Hit Area หรือรายการจังหวัดที่คลิกได้อย่างถูกต้อง ไม่ใช้การประมาณตำแหน่งแบบคลาดเคลื่อน

### การทดสอบ

ทดสอบคลิกครบทั้ง 9 จังหวัด รวมถึง:

- โหมดปี 2022
- โหมดปี 2023
- โหมดเปรียบเทียบสองปี
- อุณหภูมิ
- ความชื้น
- ปริมาณฝน
- จุดความร้อน
- หลังเปลี่ยน Filter
- ระหว่างและหลัง Animation
- หลัง Scroll หรือ Resize หน้าจอ

หลังคลิกต้องตรวจว่า:
1. Province Filter ตรงกับจังหวัดที่คลิก
2. Active Filter Chip ตรงกัน
3. แผนที่ Highlight จังหวัดถูกต้อง
4. KPI และกราฟอื่นอัปเดตถูกต้อง
5. การคลิกซ้ำเพื่อกลับภาพรวมทำงานตามที่กำหนด
6. ไม่มีจังหวัดอื่นถูกเลือกแทน

## PART 2 — ทำ Dashboard ให้สำรวจเพื่อตอบประเด็นวิเคราะห์ได้ครบ

ต้องการให้ผู้ใช้ค้นพบคำตอบผ่านระบบ Interactive โดยไม่ต้องแสดงคำถามทั้งหมดเป็นรายการ

ประเด็นที่ Dashboard ต้องรองรับมีดังนี้:

### การสำรวจภูมิอากาศบนพื้นที่สูง

ผู้ใช้ต้องสามารถ:
- ดูแนวโน้มอุณหภูมิ ความชื้น ปริมาณฝน และความเร็วลมรายเดือน
- เลือกปี 2022 หรือ 2023
- เปรียบเทียบสองปี
- เลือกจังหวัดจาก 9 จังหวัด
- เลือกสถานีตรวจวัด
- เปรียบเทียบข้อมูลหลายจังหวัด
- ดูอันดับจังหวัดที่มีค่าสูงสุดและต่ำสุด
- ดูจังหวัดที่เปลี่ยนแปลงมากที่สุดระหว่างสองปี
- ตรวจสอบช่วงเดือนที่ฝนสูงหรือต่ำโดดเด่นภายในชุดข้อมูล

ใช้ Line Chart, Bar Chart, Ranking และ Boxplot ที่มีอยู่เดิมหรือปรับปรุงจากเดิมตามความเหมาะสม

ไม่ต้องสร้างกราฟซ้ำหากกราฟเดิมตอบประเด็นได้แล้ว

หากเพิ่มการจัดอันดับ ให้มีทั้งค่าสูงสุดและต่ำสุด และสามารถคลิกจังหวัดเพื่อดูรายละเอียดได้

### การเปรียบเทียบฝนบนพื้นที่สูงกับฝนระดับจังหวัด

ต้องมีส่วนที่ผู้ใช้สามารถ:
- เลือกจังหวัด
- เลือกสถานีตรวจวัดในจังหวัดนั้น
- เลือกปีและช่วงเดือน
- เปรียบเทียบข้อมูลฝนของสถานีกับข้อมูลฝนระดับจังหวัด HII
- ดูว่าทั้งสองแหล่งมีแนวโน้มขึ้นลงสอดคล้องกันหรือไม่
- เปลี่ยนไปเลือกสถานีอื่นภายในจังหวัดเดียวกัน
- ดูจังหวัดหรือสถานีที่มีรูปแบบฝนแตกต่างจากข้อมูลจังหวัดมาก

**ข้อกำหนดด้านความถูกต้อง**

ต้องตรวจนิยาม หน่วย และวิธีสรุปข้อมูลจริงของทั้งสองแหล่งก่อน

โปรเจกต์เดิมมีข้อกำหนด `rainfallComparable = false` ดังนั้นห้ามนำฝนสถานีและ HII มาลบกันเป็นผลต่างมิลลิเมตรโดยตรง จนกว่าจะมีหลักฐานว่าค่าเหล่านั้นเทียบกันเชิงปริมาณได้อย่างถูกต้อง

ถ้ายังเทียบผลต่างเชิงปริมาณไม่ได้ ให้เปรียบเทียบแนวโน้มจากเดือนที่จับคู่กันจริง และสามารถแสดงความสอดคล้องของรูปแบบการเปลี่ยนแปลงได้

ไม่ต้องสร้างอันดับ "ผลต่างฝนมากที่สุด" หากวิธีคำนวณยังไม่ถูกต้อง

ข้อมูลสถานีหนึ่งแห่งไม่ใช่ตัวแทนของทั้งจังหวัด

### การสำรวจจุดความร้อน

ต้องสามารถ:
- ดูจำนวนจุดความร้อนที่ดาวเทียมตรวจพบรายเดือน
- ดูจำนวนจุดความร้อนแยกจังหวัด
- เรียงอันดับมากไปน้อยและน้อยไปมาก
- เลือกจังหวัดจากกราฟหรือแผนที่
- ดูการเปลี่ยนแปลงระหว่างปี 2022 และ 2023
- สำรวจข้อมูลระดับอำเภอหรือพื้นที่ย่อยเมื่อข้อมูลรองรับ

ใช้ข้อมูล VIIRS จริง โดยไม่ตีความจุดตรวจพบเป็นเหตุไฟป่าที่ยืนยันแล้ว

### การศึกษาความสัมพันธ์ระหว่างฝนกับจุดความร้อน

ผู้ใช้ต้องสามารถ:
- เลือกจังหวัด
- เลือกปีและเดือน
- ดูปริมาณฝนและจำนวนจุดความร้อนในช่วงเวลาเดียวกัน
- ดูกราฟ Scatter Plot
- ดูค่าสหสัมพันธ์จากข้อมูลคู่ที่มีจริง
- ดูว่าเดือนที่ฝนน้อยมีจุดความร้อนมากขึ้นหรือไม่
- สำรวจจังหวัดและเดือนที่มีฝนต่ำแต่จุดความร้อนสูง

ให้เพิ่มหรือปรับกราฟวิเคราะห์ร่วมที่จำเป็น เช่น:

**Rainfall vs Hotspot Scatter Plot**

แต่ละจุดแทนจังหวัด–เดือนที่จับคู่ได้จริง

ให้มี Tooltip แสดง:
- จังหวัด
- ปี
- เดือน
- ปริมาณฝน
- จำนวนจุดความร้อน

และแสดงค่า Pearson Correlation พร้อมจำนวนคู่ข้อมูลที่ใช้

**Low Rainfall / High Hotspot Explorer**

ให้แสดงจังหวัด–เดือนที่มีฝนต่ำและจำนวนจุดความร้อนสูงตามเกณฑ์ที่กำหนดจากข้อมูลจริง

ต้องระบุเกณฑ์ "ต่ำ" และ "สูง" ให้ชัด เช่น การเทียบกับ Percentile หรือการกระจายของข้อมูลที่เหมาะสม

แสดงผลผ่าน Scatter Plot แบบแบ่งพื้นที่หรือรายการที่กรองต่อได้

คลิกจุดแล้วเชื่อมไปยังจังหวัดและเดือนนั้นบน Dashboard

ห้าม Hard-code ชื่อจังหวัดที่ต้องเฝ้าระวัง

ห้ามสรุปว่าฝนน้อยเป็นสาเหตุให้เกิดจุดความร้อนโดยตรง

## PART 3 — ระบบ Filter ต้องช่วยให้ค้นพบคำตอบ

รักษา Global Filters เดิม:
- ปี
- เดือน
- จังหวัด
- อำเภอ
- ตำบล
- สถานี
- แหล่งข้อมูล
- ตัวชี้วัด
- ตัวกรองจุดความร้อน

เมื่อผู้ใช้เลือกข้อมูลจากกราฟหรือแผนที่ ให้เชื่อม Filter เท่าที่ข้อมูลรองรับ

ทุกกราฟต้องแสดงขอบเขตข้อมูลของตัวเองอย่างถูกต้อง

ตัวอย่าง:
- เลือกจังหวัดน่าน → กราฟจังหวัดเปลี่ยนเป็นข้อมูลน่าน
- เลือกสถานีในน่าน → กราฟสถานีเปลี่ยนเป็นข้อมูลสถานีที่เลือก
- ฝน HII ยังคงเป็นข้อมูลระดับจังหวัด ไม่ใช่ฝนระดับสถานี
- จุดความร้อนระดับจังหวัดต้องไม่ถูกอ้างว่าเป็นจำนวนจุดภายในสถานี
- การเลือกปีและเดือนต้องส่งผลกับกราฟที่เกี่ยวข้องทั้งหมด

เมื่อข้อมูลไม่รองรับ Filter ระดับละเอียด ให้แสดงคำอธิบายสั้น ๆ ว่าข้อมูลยังอยู่ระดับใด

ห้ามแสดงค่าผิดหรือใช้ค่า 0 แทนข้อมูลที่ไม่มี

## PART 5 — ตรวจข้อมูลก่อนคำนวณ

ใช้ไฟล์ JSON จริงใน Workspace และตรวจการจับคู่ข้อมูลด้วย Year, Month, Province และ Station ID ตามความละเอียดของแต่ละ Dataset

ขอบเขตปีของโปรเจกต์นี้คือ **2022–2023 (พ.ศ. 2565–2566)**

อย่าเปลี่ยนเป็นปี 2024–2025 โดยไม่มีข้อมูลใหม่

ตรวจเป็นพิเศษ:
- ความครบถ้วนของข้อมูลรายเดือน
- จำนวนสถานีแต่ละจังหวัด
- ปี 2023 ที่ข้อมูลสถานีไม่ครบทั้ง 12 เดือน
- วิธีคำนวณค่าเฉลี่ยรายสถานีและจังหวัด
- การเปรียบเทียบช่วงเดือนเดียวกัน
- หน่วยและนิยามฝน HII
- ความถูกต้องของจำนวนจุดความร้อน
- ความแตกต่างของระดับข้อมูลรายสถานีและรายจังหวัด
